# 12. Glossário

Termos do domínio (ontologias e extração de informação biomédica) e termos técnicos usados nesta documentação, em ordem alfabética. Quando o termo corresponde a um nome no código, ele aparece entre crases.

| Termo | Definição |
|---|---|
| Alinhamento | Ao atualizar uma ontologia externa, reaproveitar as classes que ela já tem (pelo rótulo, pelo sinônimo exato ou pelo nome) em vez de criar classes paralelas. O que falta é criado no namespace do OMAKER (`omaker/ontology/alignment.py`; [registro 0012](../decisoes/0012-atualizacao-alinhada-a-hierarquia.md)). |
| `AllDisjoint` | Axioma OWL, criado pelo owlready2, que declara um grupo de classes disjuntas entre si. Ver Disjunção. |
| Armadilha | No gabarito pequeno (`omaker/evaluation/gold/samples.json`), par de entidades que o texto menciona sem afirmar relação (negação, mera coocorrência). Prever uma relação para ele é contado à parte no relatório. |
| Arquivo de calibração | Arquivo JSON ao lado do checkpoint, com o mesmo nome e o sufixo `.calibration.json` (por exemplo `omaker_pure.calibration.json`). Guarda a temperatura e o limite de confiança. `RelationExtractorPURE.load` o lê sozinho; sem ele, valem temperatura 1 e limite 0,70 (`sidecar_path` em `omaker/relations/calibration.py`). |
| BC5CDR | Corpus BioCreative V CDR: resumos do PubMed anotados com químicos, doenças e relações de indução. Um NER treinado nele (`judithrosell/BC5CDR_PubMedBERT_NER`) é o candidato a substituir o NER atual, troca ainda **Proposta** ([registro 0014](../decisoes/0014-troca-do-ner-bc5cdr.md)). |
| BioRED | Corpus de relações biomédicas (Luo et al., 2022) com resumos do PubMed e divisão oficial em treino, validação e teste (400, 100 e 100 resumos). As relações são anotadas por resumo, entre conceitos. É a fonte de treino do PURE e do gabarito de ponta a ponta (`omaker/relations/biored.py`, `omaker/evaluation/biored_gold.py`). |
| Bootstrap | Reamostragem com reposição usada para estimar o intervalo de confiança de uma métrica. O OMAKER usa 1000 reamostragens com semente fixa (`bootstrap_ci` em `omaker/evaluation/metrics.py`). |
| Checkpoint | Arquivo com os pesos treinados do classificador PURE (`omaker_pure.pt`): `state_dict` (encoder e cabeça), nome do encoder, rótulos, tipos de entidade e os hashes das frases de treino. Fica na raiz do repositório ou, no `.exe`, em `%LOCALAPPDATA%\OMAKER\models` (`omaker/paths.py`). |
| Classe | Na OWL, um conjunto de indivíduos que compartilham uma definição (por exemplo `Analgesic`). As classes formam uma hierarquia por `rdfs:subClassOf`. |
| Classe-base | As classes fixas que correspondem aos tipos de entidade: `Drug`, `Symptom`, `Disease` e `Gene` (`BASE_CLASSES` em `omaker/domain/labels.py`). O LLM não pode redefini-las. |
| Classe raiz | `BiomedicalEntity`, a classe acima das classes-base nas ontologias geradas pelo OMAKER (`ROOT_CLASS` em `omaker/domain/labels.py`). Também serve para reconhecer uma ontologia externa: ela não tem essa classe. |
| Contaminação | Uma frase do gabarito de avaliação que também estava nos dados de treino, o que inflaria a métrica. A avaliação compara o sha256 de cada frase do gabarito com os hashes guardados no checkpoint (`contamination` em `omaker/evaluation/e2e.py`). |
| Disjunção | Axioma que diz que duas ou mais classes não têm membros em comum. O OMAKER declara as classes-base disjuntas e aceita grupos propostos pelo LLM, desde que não sejam ancestral e descendente; não impõe disjunção a classes de uma ontologia externa (`omaker/ontology/builder.py`). |
| Divisão fixa | Separação dos exemplos em treino, validação e teste, sorteada uma vez com semente e gravada com manifesto, para ser relida, e não sorteada de novo (`omaker/relations/data.py`). |
| ECE | Erro de calibração esperado (Expected Calibration Error): média, ponderada pelo número de exemplos, da diferença entre a confiança média e a taxa de acerto em 10 faixas de confiança. Zero quando a confiança é a probabilidade real de acerto (`ece` em `omaker/relations/calibration.py`). No teste do BioRED, caiu de 0,271 para 0,055 com a calibração. |
| Entidade | Algo nomeado no texto com um dos tipos do OMAKER: `DRUG`, `SYMPTOM` ou `DISEASE` (o tipo `GENE` existe, mas nenhum extrator o produz). Representada por `Entity` em `omaker/domain/entities.py`. |
| Época | Uma passada completa pelos dados de treino. O PURE do BioRED foi treinado por 5 épocas; 10 não melhoram (micro-F1 0,740 contra 0,739). |
| `equivalentClass` | `owl:equivalentClass`: axioma que declara duas classes equivalentes (mesmos membros). A página de Sinônimos o grava entre as classes de cada grupo de sinônimos, numa cópia da ontologia (`add_equivalences` em `omaker/ontology/builder.py`). |
| Executável leve (`.exe` leve) | O `OMAKER.exe` montado pelo PyInstaller sem os modelos dentro: 771 MB descompactado, 296 MB no `.zip`. Os modelos são baixados na primeira execução ([registro 0008](../decisoes/0008-executavel-leve-com-download.md)). |
| F1 | Média harmônica da precisão e da revocação: 2PR / (P + R). |
| F1 estrito | Métrica principal da avaliação de ponta a ponta. No gabarito pequeno, uma tripla prevista só conta como acerto se sujeito e objeto forem iguais aos do gabarito depois de normalizados (`norm_term`) e a relação for a mesma. No gabarito do BioRED, cada nome previsto é ligado aos conceitos anotados com esse nome (`omaker/evaluation/e2e.py`, `omaker/evaluation/biored_gold.py`). |
| F1 tolerante | Métrica de comparação da avaliação de ponta a ponta em que um nome contido no outro também casa ("diabetes" casa "type 2 diabetes"). Não é a métrica principal. |
| Filtro de domínio | Regra que descarta triplas cujo sujeito não pode ter a relação: `treats` e `prevents` exigem um fármaco como sujeito (`RELATION_DOMAIN` em `omaker/domain/labels.py`; `filter_by_domain` em `omaker/pipeline/engine.py`). |
| Gabarito | Conjunto de respostas corretas contra o qual o sistema é medido. O OMAKER tem dois para a avaliação de ponta a ponta: o pequeno, escrito à mão (`samples.json`), e o teste oficial do BioRED (100 resumos, 164 pares químico e doença). |
| Held-out | Parte do gabarito reservada, que não foi usada para ajustar o sistema; no gabarito pequeno, os documentos marcados `heldout` têm o F1 reportado à parte. |
| HermiT | Raciocinador OWL, escrito em Java e distribuído com o owlready2. O OMAKER o executa ao fim de cada geração ou atualização para conferir a consistência e materializar inferências (`run_reasoner` em `omaker/ontology/builder.py`). |
| Hugging Face | Repositório público de modelos de onde o `transformers` e o `sentence-transformers` baixam o NER, o SpanBERT e o Sentence-BERT no primeiro uso. |
| `HybridEngine` | O motor do OMAKER (`omaker/pipeline/engine.py`): extrai entidades e relações, pede a taxonomia e monta a ontologia. Não depende da interface; recebe uma função de log. |
| Instância | Na OWL, um indivíduo, membro de uma classe. Cada entidade encontrada no texto vira uma instância da classe mais específica aceita para ela, com o nome original em `rdfs:label`. |
| Intervalo de confiança | Faixa de valores plausíveis para uma métrica, dada a amostra. O micro-F1 do PURE no teste do BioRED é 0,739, com IC de 95% de 0,694 a 0,785. |
| IRI | Internationalized Resource Identifier: o identificador global de uma ontologia e de cada entidade nela. A OWL 2 exige IRI absoluto para a ontologia; o OMAKER corrige uma base vazia ou inválida para `http://www.mestrado.edu/ontologias/` (`omaker/ontology/iri.py`). |
| Limite de confiança | Confiança mínima para uma relação prevista pelo PURE ser mantida; abaixo dele, ela vira `no_relation`. É 0,35 com o modelo publicado, escolhido na validação, e 0,70 quando não há arquivo de calibração (`DEFAULT_CONFIDENCE_THRESHOLD`). |
| LLM | Modelo de linguagem grande. No OMAKER, roda localmente pelo Ollama e propõe entidades, a taxonomia e, sem checkpoint, as relações; tudo o que ele devolve é conferido pelo código (`omaker/llm/`). |
| `LLMError` | Exceção do cliente do Ollama para qualquer falha do LLM: Ollama fora do ar, modelo não instalado, resposta no limite de tokens ou JSON inválido depois das novas tentativas (`omaker/llm/client.py`). |
| Macro-F1 | Média simples do F1 de cada relação presente no gabarito, sem `no_relation`. Dá o mesmo peso a classes raras e frequentes. |
| Manifesto | Arquivo `manifest.json` gravado com a divisão dos dados: semente, frações, sha256 do arquivo de origem, se a divisão foi estratificada e as contagens por relação. |
| Marcador tipado | Token especial inserido em volta do sujeito e do objeto antes da codificação, com o papel e o tipo da entidade, por exemplo `<S:DRUG> Paracetamol </S:DRUG> treats <O:SYMPTOM> fever </O:SYMPTOM>` (`mark_text` em `omaker/relations/model.py`; `marker_tokens` em `omaker/domain/labels.py`). |
| Menção | Uma ocorrência de uma entidade no texto, com posição de início e fim. Uma entidade pode ter várias menções; o LLM-NER cria uma por ocorrência achada. |
| Micro-F1 | F1 calculado sobre a soma dos acertos, falsos positivos e falsos negativos de todas as relações positivas, sem `no_relation`. É a métrica principal do classificador (`classification_prf` em `omaker/evaluation/metrics.py`). |
| NER | Reconhecimento de entidades nomeadas (Named Entity Recognition): achar e tipar os nomes no texto. O OMAKER usa o `d4data/biomedical-ner-all`, frase a frase, e mapeia os rótulos dele para `DRUG`, `SYMPTOM` e `DISEASE` (`omaker/nlp/ner.py`). F1 0,409 nas menções do teste do BioRED. |
| `no_relation` | Rótulo de um par de entidades sem relação. É uma das quatro classes do PURE, mas fica fora do micro-F1. |
| Ollama | Servidor local de LLMs, com uma API HTTP (por padrão em `http://localhost:11434`). O OMAKER usa `/api/tags` e `/api/chat`, com saída em esquema JSON (`omaker/llm/client.py`). |
| Ontologia | Representação formal de um domínio: classes, indivíduos, propriedades e axiomas lógicos que um raciocinador pode conferir. O OMAKER gera uma ontologia OWL a partir de texto, como rascunho para revisão no Protégé. |
| OWL | Web Ontology Language, linguagem do W3C para ontologias, baseada em lógica de descrição. O OMAKER grava em RDF/XML. |
| owlready2 | Biblioteca Python para criar, carregar e salvar ontologias OWL e chamar o HermiT (`omaker/ontology/builder.py`). |
| Par candidato | Duas entidades na mesma frase cujos tipos formam um par permitido (`ALLOWED_TYPE_PAIRS` em `omaker/domain/labels.py`). Só pares candidatos são classificados (`generate_pairs` em `omaker/nlp/pairs.py`). |
| Precisão | Fração das previsões que estão certas: acertos / (acertos + falsos positivos). |
| Protégé | Editor de ontologias da Universidade de Stanford. O OMAKER abre nele a ontologia gerada e pode usar o Java que vem com ele para o HermiT (`omaker/ontology/protege.py`, `omaker/ontology/java.py`). |
| PubTator | Formato de texto em que o BioRED é distribuído: título e resumo, depois uma linha por menção e por relação (`parse_pubtator` em `omaker/relations/biored.py`). |
| PURE | Abordagem de extração de relações de Zhong e Chen (2021) que marca o sujeito e o objeto com marcadores tipados e classifica o par a partir das representações dos marcadores de abertura. No OMAKER, é o classificador de relações treinado pela equipe, sobre o SpanBERT (`RelationExtractorPURE` em `omaker/relations/model.py`; [registro 0004](../decisoes/0004-classificador-pure-marcadores-tipados.md)). |
| PyInstaller | Ferramenta que empacota o programa Python e suas dependências numa pasta com o `OMAKER.exe` (`OMAKER.spec`). |
| `QSettings` | Armazenamento de preferências do Qt. O OMAKER guarda nele, no registro do Windows, o modelo, a temperatura, as pastas e o caminho do Protégé (`omaker/ui/pages/settings.py`). |
| Queda controlada | Troca de um componente que falhou ou falta por um substituto menos bom, avisada no log: LLM no lugar do PURE sem checkpoint, só o NER quando o LLM falha no modo `both`, ontologia sem validação quando falta o Java ([seção 8.5](08-conceitos-transversais.md#85-tratamento-de-erros)). |
| qwen3 | Família de LLMs abertos da Alibaba. O modelo padrão do OMAKER é `qwen3:8b` (`DEFAULT_MODEL` em `omaker/llm/client.py`); os experimentos usaram `qwen3:8b-q4_K_M`. O Ollama exige o nome exato do modelo instalado. |
| Raciocinador (reasoner) | Programa que deduz as consequências lógicas de uma ontologia e detecta inconsistências. O OMAKER usa o HermiT. |
| `ReasonerStatus` | Resultado do raciocinador: `CONSISTENT`, `INCONSISTENT` ou `UNAVAILABLE` (não rodou). A mensagem final da interface depende dele (`omaker/ontology/builder.py`, `omaker/ui/messages.py`). |
| Release | Versão publicada no GitHub, com arquivos anexos. `v0.3.0` traz o `OMAKER-windows.zip`; `pure-biored-v1` traz o checkpoint (438 MB), o arquivo de calibração e os sha256. |
| Retomada | Continuar uma tarefa longa interrompida a partir do último ponto gravado: `last.pt` no treino, `partial-<sistema>.json` na avaliação, arquivo `.part` com `Range` no download ([seção 8.3](08-conceitos-transversais.md#83-retomada-de-tarefas-longas)). |
| Revocação | Fração das respostas do gabarito que o sistema encontrou: acertos / (acertos + falsos negativos). |
| Self-check | Modo `OMAKER.exe --self-check arquivo.txt`, que importa todos os módulos do pipeline, instancia modelos mínimos sem download e confere os arquivos de dados, gravando o resultado num arquivo. Roda no CI depois de cada montagem do `.exe` (`omaker/self_check.py`). |
| Sentence-BERT | Modelo que transforma frases e termos em vetores comparáveis por similaridade de cosseno. O OMAKER usa o `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` e agrupa os termos com agrupamento aglomerativo, com distância limite de 0,25 (`omaker/nlp/synonyms.py`). |
| Sinônimo exato | Anotação `oboInOwl:hasExactSynonym`, usada por ontologias como a Symptom Ontology. O alinhamento a consulta depois do rótulo (`build_label_index` em `omaker/ontology/alignment.py`). |
| Span | Intervalo de caracteres (início, fim) de uma menção no texto ou na frase. O PURE recebe os spans do sujeito e do objeto, relativos à frase. |
| SpanBERT | Variante do BERT pré-treinada mascarando trechos contíguos de texto, o que favorece representações de trechos. É o encoder do PURE: `SpanBERT/spanbert-base-cased`, em inglês (`MODEL_NAME` em `omaker/domain/labels.py`). |
| Supervisão distante | Rotular exemplos automaticamente a partir de uma fonte externa, em vez de anotá-los um a um. No OMAKER, cada frase recebe a relação que o BioRED anota para o resumo inteiro, mesmo que a frase não a afirme; parte dos rótulos é, portanto, ruído ([seção 11](11-riscos-e-debito-tecnico.md)). |
| Symptom Ontology | Ontologia de sintomas (SYMP), distribuída com o OMAKER em `omaker/resources/symp.owl`. É a ontologia externa padrão da página de Sinônimos e o caso de teste do alinhamento. |
| Taxonomia | Hierarquia de classes proposta pelo LLM para as entidades achadas: subclasses, a classe de cada instância e grupos disjuntos. Só entra na ontologia depois de `validate_taxonomy` (`omaker/llm/taxonomy.py`). |
| Temperatura (calibração) | Número T pelo qual os logits do PURE são divididos antes do softmax. T maior que 1 reduz a confiança de um modelo confiante demais, sem mudar a classe prevista. Ajustada na validação; com o modelo publicado, T = 4,33 ([registro 0007](../decisoes/0007-calibracao-por-temperatura.md)). |
| Temperatura (LLM) | Parâmetro de amostragem do LLM: quanto menor, mais previsível a resposta. A avaliação usa 0, com semente fixa; a interface usa o valor das Configurações (0,1 por padrão). |
| Tripla | Uma relação na forma (sujeito, relação, objeto), por exemplo (Aspirin, prevents, stroke). Na ontologia, vira uma asserção de propriedade entre dois indivíduos. |
| uv | Gerenciador de pacotes e ambientes Python usado para instalar e rodar o OMAKER a partir do código-fonte (`uv sync --extra dev`, `uv run python -m omaker`). |
| Worker | Thread do Qt (`QThread`) que roda uma tarefa longa fora da thread da interface e se comunica só por sinais: `PipelineWorker` para o motor e `SynonymWorker` para os sinônimos (`omaker/ui/workers.py`). |
